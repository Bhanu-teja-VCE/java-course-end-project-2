Unit I • OOP, Inheritance & Dynamic Dispatch

Core domain entities inherit from the abstract Player class which implements the Rateable contract. Role-specific behavior and impact scoring dynamically dispatch at runtime. 

public abstract class Player implements Rateable {
    protected final String name;
    protected int battingRating;
    protected int bowlingRating;

    // Unit I: Abstract method enforced on subclasses
    public abstract double calculateImpactScore();
}

public class Batter extends Player {
    // Unit I: Dynamic Method Dispatch
    @Override
    public double calculateImpactScore() {
        return battingRating * 1.5 + fieldingRating * 0.5;
    }
}

Unit II • Concurrency, Monitors & Exceptions

Multi-threaded auctioneer coordinates 4 AI bidding bots using Java synchronized monitors, wait(), and notifyAll() loops with strict lock ordering to prevent deadlocks. 

// Unit II: Wait/Notify monitor synchronization
public synchronized void placeBid(BiddingBot bot, long amount) 
    throws BudgetExceededException, SquadFullException {
    
    while (isTimerExpired) {
        wait(50); // Safe condition re-check
    }
    if (amount > bot.getTeam().getRemainingBudget()) {
        throw new BudgetExceededException(bot.getTeam().getName());
    }
    this.currentHighestBid = amount;
    this.winningTeam = bot.getTeam();
    notifyAll(); // Wake waiting rival bots
}

4. Student Viva-Voce Defense Guide

Q1: Why did you implement auction bots with core Thread and wait/notify instead of ExecutorService?

Answer: The VCE-R25 Unit II syllabus emphasizes the fundamental Java thread life cycle and monitor mechanics. Using synchronized blocks, explicit locks, and wait()/notifyAll() allows us to demonstrate exact thread arbitration and avoid non-deterministic race conditions without obscuring concurrency behind high-level abstraction frameworks.

Q2: How is the Net Run Rate (NRR) mathematically computed and kept sorted?

Answer: NRR is calculated as $(\text{Total Runs Scored} / \text{Overs Faced}) - (\text{Total Runs Conceded} / \text{Overs Bowled})$. If a team is bowled out, overs faced is penalized to the full 20.0 overs. Standings are maintained dynamically in a TreeSet<PointsTableEntry> that implements Comparable, sorting first by points, then by NRR descending.

Q3: What happens when the system is run without a running MySQL server?

Answer: The system utilizes the Repository Pattern. On startup, Database.isAvailable() attempts to ping MySQL with a 2-second timeout. If the database is unavailable, it gracefully falls back to InMemoryTournamentRepository, logging run data to memory and disk using Java Object Serialization (TournamentSerializer) without throwing unhandled exceptions.
